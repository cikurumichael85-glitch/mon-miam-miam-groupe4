## Règles de responsabilité

Chaque issue précise le responsable proposé et le relecteur. L'auteur explique son changement et ses tests ; le relecteur contrôle critères, droits, cohérence et lisibilité. Michael coordonne les livraisons depuis develop vers main, sans remplacer les contributions personnelles des autres.

Chaque membre utilise son identité réelle. On ne crée pas de commits attribués à une personne absente ni de faux avis de relecture. Une contribution assistée doit être comprise et vérifiée par son auteur. Le tableau [CONTRIBUTIONS.csv](CONTRIBUTIONS.csv) reçoit les liens de commits et PR réels.

Jira reste la référence du suivi fonctionnel ; les issues GitHub servent au travail technique. Les propositions de responsables GitHub ne remplacent pas une validation collective ni un changement automatique des assignations Jira.
